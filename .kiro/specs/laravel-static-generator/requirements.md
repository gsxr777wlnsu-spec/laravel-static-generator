# Requirements Document

## Introduction

Система генерации статических HTML-сайтов на базе Laravel с административной панелью, поддержкой мультисайтов, AI-интеграцией для наполнения контентом и автоматическим деплоем на изолированные production-серверы. Система использует Blade как генератор шаблонов с сохранением чистого HTML, обеспечивает полное SEO-покрытие и разделение админки и production-сайтов на отдельных серверах.

Административная панель построена на Tailwind CSS v4.0.7 с поддержкой темной и светлой тем, обеспечивает полную редактируемость всего контента сайта включая мета-поля и медиафайлы. Система поддерживает быстрое клонирование сайтов на основе локальной staging-папки и индивидуальную настройку доступа к удаленным серверам для каждого сайта, что позволяет деплоить проекты на разные production-серверы.

## Glossary

- **Admin Server**: Сервер Debian с Laravel-приложением, базой данных и генератором HTML
- **Production Server**: Изолированный сервер Debian, содержащий только статические HTML-файлы без PHP и БД
- **Staging**: Промежуточная среда для тестирования сгенерированного HTML перед публикацией (локальная папка, также служит резервной копией)
- **Site**: Отдельный веб-сайт в мультисайтовой системе
- **Page**: Страница сайта с уникальным URL и контентом
- **Section**: Контентный блок страницы (текст, список, таблица, hero, FAQ и т.д.)
- **Template Set**: Набор Blade-шаблонов для определенного типа сайта
- **HTML Generator**: Сервис Laravel для рендеринга Blade-шаблонов в статический HTML
- **Deploy User**: Специальный пользователь SSH с ограниченными правами для деплоя
- **Media Manager**: Компонент для управления изображениями и медиафайлами
- **Admin Panel**: Административная панель на базе Laravel с интерфейсом на Tailwind CSS v4.0.7
- **Remote Server Configuration**: Настройки доступа к удаленному серверу (SFTP/SSH) для конкретного сайта
- **AI Agent**: Сервис для автоматической генерации Blade-шаблонов из Markdown-шаблонов с использованием AI-моделей
- **AI Agent Config**: Конфигурация AI-агента с API-ключами, выбранной моделью и ограничениями доступа
- **Site Redirect**: Правило редиректа для сайта с исходным путем, целевым путем и HTTP-кодом статуса
- **Nginx Config Service**: Сервис для генерации и обновления конфигурационных файлов Nginx на Production Server
- **Bulk Edit**: Массовое редактирование контента нескольких сайтов одновременно

## Requirements

### Requirement 1

**User Story:** Как администратор системы, я хочу управлять несколькими сайтами из одной админ-панели, чтобы эффективно поддерживать множество проектов.

#### Acceptance Criteria

1. WHEN администратор создает новый сайт THEN Admin Server SHALL сохранить запись с уникальным идентификатором, доменом, набором шаблонов и путем вывода
2. WHEN администратор выбирает Template Set для нового сайта THEN Admin Server SHALL создать базовую структуру страниц на основе выбранного шаблона
3. WHEN администратор просматривает список сайтов THEN Admin Server SHALL отобразить все сайты с их статусами, доменами и датами последней генерации
4. WHEN администратор клонирует существующий сайт THEN Admin Server SHALL скопировать структуру страниц и контентные блоки без копирования домена и sitemap
5. WHEN администратор удаляет сайт THEN Admin Server SHALL удалить все связанные страницы, секции и медиафайлы из хранилища

### Requirement 2

**User Story:** Как контент-менеджер, я хочу создавать и редактировать страницы с SEO-метаданными, чтобы обеспечить высокую видимость в поисковых системах.

#### Acceptance Criteria

1. WHEN контент-менеджер создает новую страницу THEN Admin Server SHALL сохранить slug, title, meta_title, meta_description, meta_keywords, canonical и structured data
2. WHEN контент-менеджер вводит meta_title длиннее 60 символов THEN Admin Server SHALL отобразить предупреждение о превышении рекомендуемой длины
3. WHEN контент-менеджер вводит meta_description длиннее 160 символов THEN Admin Server SHALL отобразить предупреждение о превышении рекомендуемой длины
4. WHEN контент-менеджер сохраняет страницу с дублирующимся slug в пределах одного сайта THEN Admin Server SHALL предотвратить сохранение и отобразить ошибку
5. WHEN контент-менеджер добавляет OpenGraph данные THEN Admin Server SHALL сохранить og:title, og:description, og:image и og:type в JSON-формате
6. WHEN контент-менеджер добавляет JSON-LD разметку THEN Admin Server SHALL валидировать JSON-структуру перед сохранением

### Requirement 3

**User Story:** Как контент-менеджер, я хочу добавлять контентные блоки разных типов на страницы, чтобы создавать гибкую структуру контента.

#### Acceptance Criteria

1. WHEN контент-менеджер добавляет секцию на страницу THEN Admin Server SHALL сохранить тип секции, контент в JSON-формате и порядковый номер
2. WHEN контент-менеджер изменяет порядок секций THEN Admin Server SHALL обновить значения order для всех затронутых секций
3. WHEN контент-менеджер удаляет секцию THEN Admin Server SHALL удалить запись и пересчитать порядковые номера оставшихся секций
4. WHEN контент-менеджер сохраняет секцию типа FAQ THEN Admin Server SHALL валидировать наличие полей question и answer в JSON-контенте
5. WHEN контент-менеджер сохраняет секцию типа hero THEN Admin Server SHALL валидировать наличие обязательных полей heading и image в JSON-контенте

### Requirement 4

**User Story:** Как контент-менеджер, я хочу загружать и управлять медиафайлами с автоматической оптимизацией, чтобы обеспечить быструю загрузку сайта.

#### Acceptance Criteria

1. WHEN контент-менеджер загружает изображение THEN Media Manager SHALL сохранить файл, автоматически определить width и height и сохранить метаданные в базу данных
2. WHEN контент-менеджер загружает изображение в формате JPEG или PNG THEN Media Manager SHALL автоматически создать WebP-версию файла
3. WHEN контент-менеджер загружает изображение размером более 2MB THEN Media Manager SHALL отобразить предупреждение о большом размере файла
4. WHEN контент-менеджер сохраняет изображение без alt-текста THEN Media Manager SHALL предотвратить сохранение и запросить обязательное поле alt
5. WHEN контент-менеджер запрашивает ресайз изображения THEN Media Manager SHALL создать новую версию с указанными размерами и сохранить её в хранилище

### Requirement 5

**User Story:** Как контент-менеджер, я хочу использовать AI для массового наполнения контентом из текстовых файлов, чтобы ускорить создание страниц.

#### Acceptance Criteria

1. WHEN контент-менеджер загружает Markdown-файл THEN Admin Server SHALL распарсить структуру документа и извлечь заголовки и контент
2. WHEN контент-менеджер запускает AI-обработку текста THEN Admin Server SHALL отправить контент в AI-сервис и получить структурированные данные
3. WHEN AI-сервис возвращает результат THEN Admin Server SHALL создать секции с типами text, list и FAQ на основе полученных данных
4. WHEN AI-сервис генерирует meta-данные THEN Admin Server SHALL заполнить поля meta_title, meta_description и JSON-LD разметку
5. WHEN AI-обработка завершается THEN Admin Server SHALL сохранить все сгенерированные секции с корректными порядковыми номерами

### Requirement 6

**User Story:** Как разработчик, я хочу генерировать статический HTML из Blade-шаблонов, чтобы получить максимальную производительность на production.

#### Acceptance Criteria

1. WHEN HTML Generator обрабатывает страницу THEN Admin Server SHALL отрендерить Blade-шаблон с данными страницы и секций в строку HTML
2. WHEN HTML Generator завершает рендеринг THEN Admin Server SHALL сохранить результат в staging-хранилище по пути, соответствующему slug страницы
3. WHEN HTML Generator обрабатывает сайт целиком THEN Admin Server SHALL сгенерировать HTML для всех активных страниц сайта
4. WHEN HTML Generator обрабатывает сайт THEN Admin Server SHALL создать файлы sitemap.xml и robots.txt на основе структуры сайта
5. WHEN HTML Generator обрабатывает 1000 страниц THEN Admin Server SHALL завершить генерацию за время не более 5 минут

### Requirement 7

**User Story:** Как разработчик, я хочу использовать систему шаблонов с компонентами, чтобы обеспечить переиспользование кода и единообразие дизайна.

#### Acceptance Criteria

1. WHEN Template Set содержит layout-файл THEN HTML Generator SHALL использовать его как базовую структуру для всех страниц
2. WHEN страница содержит секцию определенного типа THEN HTML Generator SHALL включить соответствующий компонент из Template Set
3. WHEN Template Set содержит несколько вариантов компонента THEN HTML Generator SHALL выбрать компонент на основе параметров секции
4. WHEN создается новый Template Set THEN Admin Server SHALL организовать файлы в структуре layouts, components и pages
5. WHEN Template Set клонируется THEN Admin Server SHALL скопировать все файлы шаблонов в новую директорию с уникальным именем

### Requirement 8

**User Story:** Как администратор, я хочу публиковать сгенерированный HTML на production-сервер через безопасное соединение, чтобы обновлять сайты без ручного вмешательства.

#### Acceptance Criteria

1. WHEN администратор нажимает кнопку Publish THEN Admin Server SHALL проверить наличие сгенерированных HTML-файлов в staging-хранилище
2. WHEN проверка staging завершена успешно THEN Admin Server SHALL установить SFTP-соединение с Production Server используя настроенные credentials
3. WHEN SFTP-соединение установлено THEN Admin Server SHALL загрузить все HTML-файлы и медиафайлы в соответствующую директорию на Production Server
4. WHEN загрузка файлов завершена THEN Admin Server SHALL проверить успешность передачи и записать результат в лог деплоя
5. WHEN деплой завершается с ошибкой THEN Admin Server SHALL откатить изменения на Production Server и уведомить администратора

### Requirement 9

**User Story:** Как системный администратор, я хочу изолировать production-сервер от PHP и баз данных, чтобы минимизировать поверхность атаки и повысить безопасность.

#### Acceptance Criteria

1. WHEN Production Server настраивается THEN системный администратор SHALL установить только Nginx, Certbot, Fail2ban и UFW без PHP и СУБД
2. WHEN Deploy User создается на Production Server THEN системный администратор SHALL ограничить доступ только к директориям сайтов без sudo-прав
3. WHEN SSH-доступ настраивается для Deploy User THEN системный администратор SHALL разрешить подключение только с IP-адреса Admin Server
4. WHEN файлы загружаются на Production Server THEN Nginx SHALL обслуживать только статические HTML, CSS, JS и медиафайлы
5. WHEN попытка выполнить PHP-файл на Production Server THEN Nginx SHALL вернуть ошибку 403 или 404

### Requirement 10

**User Story:** Как администратор, я хочу массово развертывать сайты одной командой, чтобы автоматизировать процесс публикации.

#### Acceptance Criteria

1. WHEN администратор выполняет команду site:deploy с идентификатором сайта THEN Admin Server SHALL запустить полный цикл генерации HTML для указанного сайта
2. WHEN генерация HTML завершена THEN Admin Server SHALL создать архив со всеми файлами сайта
3. WHEN архив создан THEN Admin Server SHALL передать архив на Production Server через SFTP
4. WHEN архив передан THEN Admin Server SHALL распаковать архив в целевую директорию на Production Server
5. WHEN распаковка завершена THEN Admin Server SHALL записать информацию о деплое в лог с timestamp и статусом

### Requirement 11

**User Story:** Как разработчик, я хочу хранить шаблоны и staging HTML в GitHub, чтобы отслеживать историю изменений и обеспечить версионирование.

#### Acceptance Criteria

1. WHEN шаблон изменяется THEN Admin Server SHALL зафиксировать изменения в Git-репозитории с описательным commit message
2. WHEN staging HTML генерируется THEN Admin Server SHALL сохранить файлы в директории, отслеживаемой Git
3. WHEN администратор запрашивает историю изменений THEN Admin Server SHALL отобразить список коммитов с датами и авторами
4. WHEN администратор откатывает изменения THEN Admin Server SHALL восстановить файлы из указанного коммита
5. WHEN файлы синхронизируются с GitHub THEN Admin Server SHALL исключить из репозитория ключи доступа, production-данные и конфигурационные файлы с секретами

### Requirement 12

**User Story:** Как администратор, я хочу защитить админ-панель дополнительными мерами безопасности, чтобы предотвратить несанкционированный доступ.

#### Acceptance Criteria

1. WHEN пользователь входит в админ-панель THEN Admin Server SHALL запросить второй фактор аутентификации после проверки пароля
2. WHEN пользователь совершает более 5 неудачных попыток входа за 10 минут THEN Admin Server SHALL заблокировать IP-адрес на 30 минут
3. WHEN пользователь выполняет критическое действие THEN Admin Server SHALL записать событие в аудит-лог с timestamp, user_id и описанием действия
4. WHEN администратор просматривает аудит-лог THEN Admin Server SHALL отобразить все записи с возможностью фильтрации по пользователю, действию и дате
5. WHEN пользовательская сессия неактивна более 30 минут THEN Admin Server SHALL автоматически завершить сессию и потребовать повторную аутентификацию

### Requirement 13

**User Story:** Как контент-менеджер, я хочу видеть предварительный просмотр страницы перед публикацией, чтобы проверить корректность отображения.

#### Acceptance Criteria

1. WHEN контент-менеджер нажимает кнопку Preview THEN Admin Server SHALL сгенерировать HTML для текущей страницы во временное хранилище
2. WHEN HTML сгенерирован THEN Admin Server SHALL отобразить страницу в iframe или новой вкладке с staging-URL
3. WHEN контент-менеджер изменяет контент страницы THEN Admin Server SHALL обновить preview при следующем запросе без влияния на опубликованную версию
4. WHEN preview-страница запрашивается THEN Admin Server SHALL применить все стили и скрипты из Template Set
5. WHEN preview-страница содержит относительные ссылки THEN Admin Server SHALL корректно разрешить пути к медиафайлам и другим ресурсам

### Requirement 14

**User Story:** Как разработчик, я хочу использовать очереди для генерации больших объемов HTML, чтобы не блокировать интерфейс администратора.

#### Acceptance Criteria

1. WHEN администратор запускает генерацию сайта с более чем 100 страницами THEN Admin Server SHALL поместить задачу в очередь вместо синхронного выполнения
2. WHEN задача генерации добавлена в очередь THEN Admin Server SHALL отобразить уведомление с идентификатором задачи и статусом "в обработке"
3. WHEN worker обрабатывает задачу генерации THEN Admin Server SHALL обновлять прогресс выполнения в процентах
4. WHEN генерация в очереди завершается THEN Admin Server SHALL уведомить пользователя через интерфейс или email
5. WHEN задача генерации завершается с ошибкой THEN Admin Server SHALL записать детали ошибки в лог и отобразить сообщение пользователю

### Requirement 15

**User Story:** Как SEO-специалист, я хочу автоматически генерировать sitemap.xml и robots.txt, чтобы обеспечить корректную индексацию сайта поисковыми системами.

#### Acceptance Criteria

1. WHEN HTML Generator обрабатывает сайт THEN Admin Server SHALL создать sitemap.xml со всеми активными страницами и их приоритетами
2. WHEN страница имеет дату последнего изменения THEN Admin Server SHALL включить тег lastmod в sitemap.xml с корректным форматом даты
3. WHEN сайт содержит более 50000 URL THEN Admin Server SHALL разделить sitemap на несколько файлов и создать sitemap index
4. WHEN HTML Generator создает robots.txt THEN Admin Server SHALL включить ссылку на sitemap.xml и правила для user-agents
5. WHEN администратор настраивает правила индексации THEN Admin Server SHALL применить custom-директивы в robots.txt для указанных путей

### Requirement 16

**User Story:** Как разработчик, я хочу поддерживать hreflang для мультиязычных сайтов, чтобы корректно указывать поисковым системам языковые версии страниц.

#### Acceptance Criteria

1. WHEN страница имеет связанные языковые версии THEN HTML Generator SHALL включить теги hreflang в секцию head для всех версий
2. WHEN HTML Generator добавляет hreflang THEN Admin Server SHALL использовать корректные ISO-коды языков и регионов
3. WHEN страница является языковой версией по умолчанию THEN HTML Generator SHALL добавить тег hreflang с атрибутом x-default
4. WHEN администратор связывает страницы как языковые версии THEN Admin Server SHALL сохранить связи в базе данных для использования при генерации
5. WHEN HTML Generator обрабатывает страницу без языковых версий THEN Admin Server SHALL пропустить генерацию hreflang-тегов

### Requirement 17

**User Story:** Как администратор, я хочу мониторить статус серверов и деплоев, чтобы быстро реагировать на проблемы.

#### Acceptance Criteria

1. WHEN администратор открывает dashboard THEN Admin Server SHALL отобразить статус всех Production Servers с индикаторами доступности
2. WHEN Production Server недоступен THEN Admin Server SHALL отобразить предупреждение и время последней успешной проверки
3. WHEN администратор просматривает историю деплоев THEN Admin Server SHALL отобразить список всех деплоев с датами, статусами и длительностью
4. WHEN деплой завершается с ошибкой THEN Admin Server SHALL отправить уведомление администратору через настроенный канал
5. WHEN администратор запрашивает детали деплоя THEN Admin Server SHALL отобразить полный лог выполнения с временными метками каждого шага

### Requirement 18

**User Story:** Как администратор, я хочу использовать Tailwind CSS v4.0.7 для стилизации админ-панели, чтобы обеспечить современный и консистентный интерфейс.

#### Acceptance Criteria

1. WHEN Admin Panel загружается THEN Admin Server SHALL использовать Tailwind CSS v4.0.7 для всех стилей интерфейса
2. WHEN разработчик добавляет новый компонент UI THEN Admin Panel SHALL применять utility-классы Tailwind CSS для стилизации
3. WHEN Admin Panel рендерится THEN Admin Server SHALL включить скомпилированный CSS-файл Tailwind в HTML-документ
4. WHEN разработчик настраивает Tailwind THEN Admin Server SHALL использовать конфигурационный файл tailwind.config.js с кастомными настройками проекта
5. WHEN Admin Panel обновляется THEN Admin Server SHALL поддерживать все возможности Tailwind CSS v4.0.7 включая новые функции версии 4

### Requirement 19

**User Story:** Как пользователь админ-панели, я хочу переключаться между темной и светлой темами, чтобы работать в комфортных условиях в любое время суток.

#### Acceptance Criteria

1. WHEN пользователь открывает Admin Panel THEN Admin Server SHALL отобразить переключатель темы в интерфейсе
2. WHEN пользователь переключает тему на темную THEN Admin Panel SHALL применить темную цветовую схему ко всем элементам интерфейса
3. WHEN пользователь переключает тему на светлую THEN Admin Panel SHALL применить светлую цветовую схему ко всем элементам интерфейса
4. WHEN пользователь выбирает тему THEN Admin Server SHALL сохранить предпочтение пользователя в localStorage или базе данных
5. WHEN пользователь возвращается в Admin Panel THEN Admin Server SHALL автоматически применить ранее выбранную тему

### Requirement 20

**User Story:** Как контент-менеджер, я хочу редактировать весь контент сайта из админ-панели, включая мета-поля и медиа, чтобы иметь полный контроль над содержимым.

#### Acceptance Criteria

1. WHEN контент-менеджер открывает редактор страницы THEN Admin Panel SHALL отобразить все редактируемые поля включая title, slug, meta_title, meta_description, meta_keywords, canonical, og_data и json_ld
2. WHEN контент-менеджер редактирует секцию THEN Admin Panel SHALL позволить изменить тип секции, содержимое и порядок отображения
3. WHEN контент-менеджер работает с медиафайлами THEN Admin Panel SHALL позволить редактировать alt-текст, title, загружать новые файлы и удалять существующие
4. WHEN контент-менеджер изменяет OpenGraph данные THEN Admin Panel SHALL предоставить форму для редактирования og:title, og:description, og:image и og:type
5. WHEN контент-менеджер редактирует JSON-LD разметку THEN Admin Panel SHALL предоставить текстовый редактор с валидацией JSON-синтаксиса

### Requirement 21

**User Story:** Как администратор, я хочу быстро клонировать файлы сайта на основе локальной staging-папки, чтобы ускорить создание новых проектов.

#### Acceptance Criteria

1. WHEN администратор выбирает опцию клонирования сайта THEN Admin Panel SHALL отобразить список доступных сайтов с их staging-папками
2. WHEN администратор запускает клонирование THEN Admin Server SHALL скопировать все HTML-файлы, медиафайлы и структуру директорий из staging-папки источника
3. WHEN клонирование выполняется THEN Admin Server SHALL создать новую запись сайта в базе данных с уникальным идентификатором и доменом
4. WHEN клонирование завершается THEN Admin Server SHALL сохранить скопированные файлы в новую staging-папку для нового сайта
5. WHEN администратор просматривает клонированный сайт THEN Admin Panel SHALL отобразить все страницы и контент из исходного сайта с возможностью редактирования

### Requirement 22

**User Story:** Как администратор, я хочу настраивать доступ к удаленному серверу для каждого сайта отдельно, чтобы деплоить сайты на разные production-серверы.

#### Acceptance Criteria

1. WHEN администратор создает новый сайт THEN Admin Panel SHALL предоставить форму для ввода настроек удаленного сервера включая host, port, username, authentication method
2. WHEN администратор сохраняет настройки удаленного сервера THEN Admin Server SHALL зашифровать credentials и сохранить их в базе данных связанными с конкретным сайтом
3. WHEN администратор редактирует настройки сервера THEN Admin Panel SHALL отобразить текущие настройки с возможностью изменения host, port, username и authentication method
4. WHEN администратор тестирует подключение THEN Admin Server SHALL попытаться установить SFTP-соединение с указанными credentials и вернуть статус подключения
5. WHEN администратор запускает деплой сайта THEN Admin Server SHALL использовать настройки удаленного сервера конкретного сайта для установки SFTP-соединения и передачи файлов

### Requirement 23

**User Story:** Как разработчик, я хочу использовать AI-агента для автоматического создания Blade-шаблонов из Markdown-шаблонов, чтобы ускорить разработку новых страниц и компонентов.

#### Acceptance Criteria

1. WHEN администратор открывает настройки AI-агента THEN Admin Panel SHALL отобразить форму для конфигурации API-ключей различных AI-провайдеров включая OpenAI и Anthropic
2. WHEN администратор сохраняет конфигурацию AI-агента THEN Admin Server SHALL зашифровать API-ключи и сохранить настройки в базе данных с привязкой к пользователю
3. WHEN администратор настраивает ограничения доступа THEN Admin Server SHALL сохранить список разрешенных папок и сайтов для редактирования AI-агентом
4. WHEN разработчик запускает AI-агента с промптом и MD-шаблоном THEN AI Agent Service SHALL отправить запрос к выбранной AI-модели и получить сгенерированный Blade-код
5. WHEN AI-агент генерирует Blade-файл THEN Admin Server SHALL сохранить файл только в разрешенные директории и создать запись в аудит-логе
6. WHEN разработчик переключает AI-модель THEN Admin Panel SHALL применить новую модель для следующих запросов без потери контекста сессии
7. WHEN AI-агент пытается создать файл в запрещенной директории THEN Admin Server SHALL предотвратить операцию и вернуть ошибку доступа

### Requirement 24

**User Story:** Как администратор, я хочу массово редактировать контент сайтов и управлять редиректами с автоматическим обновлением конфигурации Nginx, чтобы эффективно управлять множеством сайтов.

#### Acceptance Criteria

1. WHEN администратор открывает страницу массового редактирования THEN Admin Panel SHALL отобразить список всех сайтов с возможностью множественного выбора
2. WHEN администратор выбирает несколько сайтов и применяет массовое изменение текста THEN Admin Server SHALL обновить указанные текстовые поля во всех выбранных сайтах
3. WHEN администратор добавляет редирект для сайта THEN Admin Server SHALL сохранить правило редиректа в базе данных с полями source_path, target_path, status_code и site_id
4. WHEN администратор сохраняет изменения редиректов THEN Nginx Config Service SHALL сгенерировать обновленный конфигурационный файл Nginx для затронутых сайтов
5. WHEN конфигурация Nginx обновлена THEN Admin Server SHALL подключиться к Production Server через SSH и выполнить команду перезагрузки Nginx
6. WHEN перезагрузка Nginx завершается THEN Admin Server SHALL проверить статус Nginx и записать результат операции в лог деплоя
7. WHEN перезагрузка Nginx завершается с ошибкой THEN Admin Server SHALL откатить изменения конфигурации и уведомить администратора об ошибке
8. WHEN администратор просматривает редиректы сайта THEN Admin Panel SHALL отобразить все активные редиректы с возможностью редактирования и удаления
